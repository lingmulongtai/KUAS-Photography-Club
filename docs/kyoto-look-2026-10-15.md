# 京都3Dの質感・色調の改善（2026-10-15）

対象は公開済みの `987096b` 以降。トップの3Dを、模型のような灰色・雪のような地面から、写真らしい見え方へ寄せる。

## 評価で見つけた問題

- 市街の家々の間の地面が白く、雪が積もったように見える。航空写真に焼き込まれた屋根・舗装の明るさが、3D建物の足元にそのまま出ていた（太秦キャンパスで最も顕著）。
- 木が影を落とさず、面の目立つ宝石のような樹冠と明るい黄緑で、地面から浮いて見える。
- 昼の画面が平板で灰色。夜は遠方の街灯が1画素に重なって飽和し、地平線に白い光の玉が並ぶ。
- 大文字山は昼に「大」が読めず、山肌に暗い斑点が目立つ。火床の線も航空写真の空地とずれていた。
- 金閣寺の池の島が、平たい板を貼ったように見える（小島が森林判定の粗いマスクで水面扱い）。
- ピンがヘッダーに重なる。操作ヒントの文字がグローバルの灰色を継承して暗いガラス上で読みにくい。スマホでは3Dの下端が見出しの途中で線になって切れる。

## 変更

- 建物の足跡を一度だけラスタ化したテクスチャ（PC2048／スマホ1024、R8＋ミップマップ）を作り、地面と壁の根元の環境遮蔽に使う。密集地の淡い無彩色の地面を街路・庭の明るさへ圧縮する。Canvasの一括パスは約25万棟でブラウザが固まるため、JSで2×2サンプルのラスタ化を行う。
- 木: 遠景の樹冠を楕円体の法線で滑らかにし、近景に葉の塊の陰影・内側の暗がり・逆光の透過を追加。太陽の影を落とす（深度用マテリアルを追加し、影マップの再描画時だけ描く）。色は写真由来のまま彩度の上乗せをやめる。
- 色調: 日中だけ、わずかなコントラスト・彩度と、影の寒色・ハイライトの暖色を加える。太陽高度−6°〜8°で徐々にかけ、夜は従来どおり。
- 遠方の街灯・車のライトは、実際より大きく描く分だけ暗くする。水面の太陽の照り返しは波で途切れるようにする。
- 大文字: 航空写真の刈り込みの線から交点と3画を引き直し（公表値80／160／120mに合わせる）、昼は乾いた草の帯として地面に描く。夜の送り火も同じ線を使う。山肌の合成した樹冠模様のコントラストを下げる。
- 池の島（12〜12,000m²の水域の穴）を森林判定に含め、粗い水域マスクから外す。島の地面は苔と石の面として重ねる。
- 写真では裸地に見える森林区域（落葉・紅葉期の写真）は樹冠の色へ強めに寄せる。
- UI: ヘッダーと視点バーをピンの回避領域に追加。ヒント文字を明るいHUD色に。スマホのスクリムを背景色まで完全に溶かす。

## 検証

- `npm test`: 34件成功（建物ラスタの被覆・回転・多角形、島の面積条件とセル境界の4件を追加）。
- `npm run check`: 129ファイル、error / warning / hint 各0。
- `npm run build`: ASCIIの検証コピーで成功（日本語OneDriveパスのネイティブ終了を避ける従来の手順）。
- PCの実GPU（RTX 4050 / ANGLE D3D11）のヘッドレスChromeで、時刻を2026-10-15 15:20に固定し、7視点＋キャンパス、昼・夕焼け・夜を変更前後で撮影して比較。シェーダーの警告・エラーなし。
- 変更前後の本番ビルドを同条件（1920×1080、DPR2）でGPU時間を計測（タイマークエリ、中央値ms）。金閣寺 25.4/25.8 → 26.1/25.3、嵐山 29.8/29.6 → 30.9/30.6、夜 28.2/29.4 → 28.3/28.3。時刻切替中（影の再描画を含む）の最大値も悪化なし。このPCの一例で、スマホの速度の保証ではない。
- 390×844（DPR3、軽量モード）のブラウザ幅で将軍塚・金閣寺・大文字・キャンパスを確認。スマホ実機の確認ではない。

## 限界

- 地面の補正と環境遮蔽は近似で、航空写真の解像度（市街約5m/画素）自体は変わらない。将軍塚の手前（円山公園・知恩院）はまだ写真のぼけが残る。
- 「大」の線は航空写真から読み取った代表形状で、火床の測量ではない。島の木は景観表現で、実際の植栽の位置ではない。
