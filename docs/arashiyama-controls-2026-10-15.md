# 嵐山と操作の改善 — 2026-10-15

## 今回の挙動

- マウスの横ドラッグを反転する。スマホで確認済みの横スワイプ方向と、縦スクロールは維持する。
- 太秦キャンパスのピンを一度押すと、そのままキャンパスへ移動する。撮影会のリンクはホバー／フォーカスで開ける。途中の移動ボタンは不要になった。
- 嵐山の近景に詳細な航空写真と標高、水域輪郭を使い、対岸の森林と上流のつながりを改善する。

## 地形・植生・水面

詳細領域はローカル座標 `[-10500,-3200,-6500,800]` の4×4km。国土地理院のシームレス写真、DEM、ベクトルタイルから `tools/kyoto-data/build_arashiyama.py` で生成する。配信中のブラウザから地図サービスへの取得はない。既存の建物・道路・鉄道・広域標高ファイルは変更しない。

| データ | 大きさ | 読み込み |
| --- | ---: | --- |
| PC写真 2048×2048 | 738,382 bytes | 嵐山を初めて選んだ時 |
| スマホ写真 1024×1024 | 227,946 bytes | 嵐山を初めて選んだ時 |
| 10m間隔の標高 401×401 | 161,533 bytes | 地形初期化時 |
| 詳細水域 | 45,611 bytes | 線データ初期化時 |

地域標高を境界120mで既存の標高へ混ぜ、法線にも使う。写真の樹冠を斜面に残し、土・苔で覆う処理は近くの平坦な林床に限定する。写真のサンプリングを空間条件分岐の外に置き、ミップレベルの微分が未定義にならないようにする。

樹木の判定と色にも地域写真を使う。写真の到着が遅れた場合は、表示中の植樹中心を保ってキャッシュを更新し、大学へ移動済みでも嵐山中心に戻らない。近景650mの植生を補強し、それより遠い候補セルは従来と同じままにする。検証地点の候補数はPC74,748、スマホ32,215で、実際の生成時には森林・建物・道路・水域・密度の判定でさらに減る。候補数のテストはPC80,000未満、スマホはその半分未満を条件にする。描画は既存のインスタンス化とチャンク単位の視錐台カリングを使う。

落葉・紅葉や青い影で緑の判定から外れる場所には、地域写真の色と斜面の条件を併用する。これは植生の近似であり、個々の木の実測配置ではない。淡い屋根、青い水、平坦な灰色地面を拒否し、建物・道路・水域の除外は先に適用する。水域マスクを詳細領域まで広げ、岸には半画素程度の余白を設ける。

水域は元の線データとチェックサムが一致する場合だけ置き換える。道路・鉄道と無関係な水域は元のオブジェクトを保つ。島の穴と岸を保つ共通辺の細分化を行い、PC18m／スマホ28mを近景の基準とし、遠方では粗くする。地域の水面はPC約34,987三角形、スマホ約18,676三角形。異常なポリゴンは上限40,000三角形で粗い細分化に戻し、読み込み失敗時には既存水域を保つ。地域標高・写真の取得失敗でも、既存の広域表示へ戻せる。
