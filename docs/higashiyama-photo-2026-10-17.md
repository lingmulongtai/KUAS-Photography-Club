# 将軍塚の手前の地域写真 — 2026-10-17

## 目的

既定の視点「将軍塚」の手前（円山公園・知恩院・高台寺・祇園）は、市街用の航空写真（約4.9m/画素）がぼけて、地面が白っぽく平坦に見えていた。嵐山と同じ方式で、手前だけに高解像度の地域写真を重ね、地面と植樹判定に使う。比較の基準は、kyoto-look-2026-10-15.md の見た目調整（ac844cf までの公開版）。

## データ

`tools/kyoto-data/build_higashiyama.py` が国土地理院のシームレス写真 z17（約0.98m/画素、108タイル）から生成する。標高（`terrain-near.bin` が既に10m間隔）、道路・水域・建物は変更しない。

| 項目 | 値 |
| --- | --- |
| 範囲（ローカル座標） | `[1000,-1000,3000,1600]`。鴨川・祇園から将軍塚の背後まで、岡崎の南端から清水寺の下の斜面までの2.0×2.6km |
| PC写真 | 1576×2048（約1.27m/画素）、743,638 bytes（上限760,000） |
| スマホ写真 | 788×1024、240,998 bytes（上限260,000） |
| 読み込み | 将軍塚・清水の舞台を初めて表示した時。既定の視点なので初期表示と並行して読み込む |

z16（約1.95m/画素）で4×4kmにすると同じ容量に収まるが、樹冠や小道が潰れる。範囲を手前に絞り、z17を画素中心で2倍に標本化してLanczosで縮小した。嵐山（738,382 / 227,946 bytes）と同程度の転送量。

## 仕組み

- `terrain.ts`: 地域写真を複数持てるようにした。写真ごとに `uPhotoBox{i}` / `uPhoto{i}` / `uPhotoOn{i}` を生成し、`setPhoto(i, texture)` で表示する。GLSLはsamplerの配列をループで添字参照できないため、領域ごとにコードを展開する。サンプリングは一様な条件（読み込み済みか）だけで分岐し、空間条件の外に置いてミップの微分を保つ。境界120mで市街写真へ混ぜる。地域標高（嵐山の `uRegional*`）は写真と切り離し、従来どおり。
- `trees.ts`: `setRegionalPhoto(photo, box, seasonal)` が領域の一覧を持つ。植樹の色と森林判定は、その地点を含む領域の写真を優先する。視点が領域内にあれば、650m以内の候補を嵐山と同じく密にする。落葉・紅葉の斜面を森として拾う補助判定は嵐山だけに使う。東山の写真は夏の樹冠で、補助判定を有効にすると大谷・鳥辺野の墓地の縁まで森として拾ったため。
- `scene.ts`: `REGIONAL_PHOTOS` で写真と視点を対応付ける（嵐山→嵐山、東山→将軍塚・清水の舞台）。視点を切り替えると、その視点の写真を一度だけ読み込む。失敗した場合は市街写真のまま表示する。

- `npm run check`: 133ファイル、error / warning / hint 各0。
- `npm run build`: ASCIIパスの検証コピーで成功。出力に2つの写真が含まれ、検証用フックがないことを確認した。
- PC実GPU（RTX 4050 Laptop、アプリ内ブラウザ、1440×900、DPR1）で変更前後を比較した。比較用のコピーにだけ、描画を手動で進めてキャンバスを保存するフックを入れた。配信用ソースには含めていない。
  - 将軍塚の昼: 手前の白いぼけが消え、小道・砂利・樹冠の形が見える。表示する木は22,016本から28,774本に増えた。
  - 夕方: 低い太陽を受ける木が増え、地面のにじみが減った。夜: 街灯・窓明かりは変わらず、森が少し濃くなるだけ。
  - 清水の舞台の昼: 背後の斜面が森として埋まり、境内周辺の地面に実際の小道が出る。木は21,238本から28,319本。
  - 描画時間（1フレームの描画とGPU同期、60フレーム×2〜3回の中央値）: 将軍塚は変更前11.1〜12.1ms、変更後11.2〜11.8ms。清水は変更前11.9〜12.0ms、変更後11.6〜12.0ms。差は測定のばらつきの範囲内。
- 嵐山: 変更前後のキャプチャはほぼ一致（差が8階調を超えた画素は5）。10km先の候補セルが東山の写真を参照するため、木が1本だけ変わる。
- 375×812のスマホ表示（同じPCで測定）: スマホ用の写真を使う。将軍塚の木は8,986本から12,353本。オーナーがスマホ実機で確認済みの嵐山（19,979本）より少ない。描画時間の中央値は7.8〜8.3msから8.0〜9.2ms。端末間の性能保証には使わない。
