# 寺院周辺の地表・植生と建物中心のカメラ

対象は公開済みの `4d220c2` 以降。金閣寺・清水寺周辺の白い地面と樹形の繰り返しを抑え、主要な建物を中心に回る操作を追加する。

## 実装

- 金閣寺・清水寺・京都タワーは建物中心の軌道カメラ。水平回転は何周でも可能で、注視点は固定する。将軍塚・船岡山・嵐山・大文字山の遠望は従来の見回しを保持する。
- 軌道上の8点で地形と樹冠の高さを確認し、建物の背後へ回ったときも視界が埋まらない高さへ調整する。植樹とクリアランスは写真・OSM・建物・水域・道路の同じ植生判定を使う。
- 航空写真に焼き込まれた明るい屋根・舗装の反射率を寺院周辺で圧縮。森林と寺院周辺の近景には土・苔・落ち葉の色むらを加える。粒状模様は画素より細かくなると平均値へ戻す。道路の位置・水面の形・時刻と空の露出は保持する。
- 木の樹種、幅、高さ、縦横比、傾き、樹冠の伸び、葉色を独立した座標ハッシュで決定する。近景から中景には65m単位の群落・空隙を作る。遠景の被覆と候補数上限、3視点分の配置キャッシュは保持する。
- 同じジオメトリと描画単位を使用し、ポリゴン数や描画回数を増やさない。追加は1インスタンス当たり3つのfloat。変形に合わせて法線とカリング範囲を補正する。写真から採った色を少量残すが、樹種と配置は景観表現であり現地の植生調査ではない。
- 名所にも「斜めから／真上から」を追加し、縦のタッチ操作はページスクロールを維持する。飛行中は回転と角度ボタンを無効にし、着地後の視点の跳びを防ぐ。同じ地点の再選択でカメラと選択表示をリセットする。

## 検証

- `npm test`: 22件成功。複数周回、注視点固定、上空・下限、斜面・樹冠のクリアランス、飛行中の入力ロック、樹種内の独立したサイズ変化、密度の連続性を含む。
- `npm run check`: 121ファイル、error/warning/hint各0。
- `npm run build`: ASCIIの検証コピーで成功。既存の日本語OneDriveパスのネイティブ終了を避け、ソースを変更せずコピーで確認する。
- PC実GPUはNVIDIA RTX4050 Laptop／ANGLE Direct3D11。地面シェーダーの予約語によるコンパイルエラーを開発中に修正し、最終ビルドで警告・エラーがないことを確認する。
- 金閣寺を実際の4回のドラッグで一周し、建物が中央に留まり元の構図へ戻ることを確認。90°・180°・270°・360°の画面を保存する。
- 清水寺の上空表示、角度リセット、飛行中に角度ボタンが無効・到着後に有効になることをブラウザで確認する。
- 大学への接近、既存の「真上から」、街へ戻る操作、金閣寺の昼夜切替を確認。ブラウザの一時的な幅・動きの軽減設定は検証後に解除する。
- 390×844のブラウザ幅で金閣寺・清水寺・京都タワーの全体が収まり、横はみ出しがないことを確認。金閣寺の上空ボタンも確認する。ブラウザ幅の変更はスマホ実機の検証とは区別する。
- 通常アニメーションの金閣寺、単独の検証タブ、描画1487×1080px、100フレームの間隔は中央値16.7ms（約60fps）、95パーセンタイル16.8ms。このPCの一例で、スマホの速度は未確定。
- 着手時の公開版では中央値24.4ms／95パーセンタイル42.4ms、描画1115×810pxだった。描画解像度・配置中心・ブラウザの状態が異なるため、改善率の直接比較には使わない。
- スケジュール、ガイドライン、連絡先、入部先、管理画面APIへの差分はない。
